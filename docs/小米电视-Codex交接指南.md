# 小米电视桌面改造：交给 Codex 的任务说明

> 使用方式：把整个文件交给能访问你本机文件、终端和局域网的 Codex，并告诉它“按照文档开始执行”。不需要预先填写全部信息；缺失的关键信息由 Codex 一次性询问。
>
> 本文是可独立使用的交接说明，不包含另一位用户的源码、APK、签名密钥、访问令牌或网络配置。只有本文时，从独立项目开始；如果另附源码，先检查现状再复用。

## 1. 给 Codex 的目标

请帮助我测试并改造我自己使用的小米电视首页，完成可安装、可操作、可持续更新的独立桌面应用。

目标是 **Apple TV 整个 tvOS 系统主屏的布局、应用卡面、焦点、动画和材质**。参考对象包括主屏和控制中心，不只是 Apple TV 视频应用。

请直接推进设备检查、开发、打包和验证，不停留在方案建议。先解决安装与真正默认首页，再完善 UI、动态背景和更新。每个阶段提供可以验证的结果，避免让我反复安装只改了名字、仍未解决核心问题的版本。

成功标准：

- 独立桌面能显示并打开实际安装的电视应用，完全支持遥控器。
- 在系统允许的情况下成为真正默认首页，物理 Home 键返回这个桌面。
- 应用卡面、排版、玻璃层次和动效达到统一的 tvOS 风格。
- 背景可以更新；有经过验证的数据源时显示“最近在看”。
- 后续版本可由电脑提供，电视检查、下载并经系统确认覆盖安装。
- 保留返回电视设置、原桌面和恢复默认首页的入口。

**当前没有对这台小米电视做兼容性验证。不要把其他品牌上的成功当作本机事实。**

## 2. 先确认设备和工作环境

先自动检查本机已有环境，只询问无法获得的信息。建议将问题合并，别一次只问一个字段。

| 信息 | 获取方式 |
| --- | --- |
| 小米/Redmi 电视具体型号、销售地区 | 用户查看设置中的关于页面 |
| 系统名称与完整版本 | 区分 MIUI TV、澎湃系统、Android TV/Google TV 等实际版本 |
| Android API、CPU ABI | 有 ADB 后读取；营销系统名不能代替 Android API |
| 电视 IP、屏幕显示的调试端口 | 电视网络/调试页面；不要借用别人的地址 |
| 电脑系统、是否与电视同一局域网 | 本机检查并让用户确认网络 |
| 可用传 APK 途径 | ADB、用户已用过的手机工具、SMB、U 盘等，选择当前可用的一条 |
| 是否已有源码或已安装的自制桌面 | 决定新建项目，还是保留原签名进行升级 |

在独立项目目录操作，先确认仓库、已有修改、SDK/JDK/Platform Tools 和构建方式。使用现有工具链，不为本任务升级无关软件。Codex 如果运行在无法访问家庭局域网的远程环境，要明确说明，并把需要在本机执行的步骤交给用户。

已有授权范围内的读取、开发、构建和针对性验证连续完成；只有电视上必须由用户完成的授权、登录或物理按键步骤才让用户操作。

## 3. 建立连接：先看实际入口

### 3.1 开发者选项和 ADB

小米官方 FAQ 给出的部分机型路径是：设置 → 关于 → 产品型号连续点击 7 次，然后在账户与安全中允许 ADB 调试。该路径是排查线索，**不保证适用于所有地区、型号和固件**；请核对本机页面和适用的官方说明。[小米官方 FAQ](https://www.mi.com/tw/support/article/KA-17750/)

根据电视实际提供的机制连接：

- 传统网络 ADB：使用已确认的 IP 和端口连接。不要反复假定端口一定是 5555。
- 标准无线调试：只有实际存在配对入口时才使用 `adb pair`；配对端口和连接端口应分别读取，不能混用。
- 只有 USB 调试：确认该型号的调试接口与连接方式，不把普通 U 盘接口直接当成电脑调试接口。
- 用户必须在电视确认网络/调试授权；“开关已开”不等于电脑已经获得授权。

执行 `adb devices -l` 确认目标状态。后续每条设备命令明确指定目标序列号，避免操作本机模拟器或另一台设备。连接失败时区分网络不通、端口未监听、未授权、配对失败及调试服务状态；有明确新证据再重试。[Android ADB 文档](https://developer.android.com/tools/adb)

连接成功后，先保存必要的只读信息。下面的 `<电视序列号>` 需替换为实际值，不能原样执行：

```sh
adb -s <电视序列号> shell getprop ro.product.model
adb -s <电视序列号> shell getprop ro.build.version.release
adb -s <电视序列号> shell getprop ro.build.version.sdk
adb -s <电视序列号> shell getprop ro.product.cpu.abilist
adb -s <电视序列号> shell wm size
adb -s <电视序列号> shell wm density
adb -s <电视序列号> shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

系统命令支持情况因版本而异；不支持时保留原始错误，改用该版本可用的查询方式，不把失败解释为“没有默认桌面”。记录原 HOME 组件、目标应用版本和后续恢复路径。

### 3.2 ADB 暂时不可用时

继续推进 APK 安装与验证，不要一直卡在寻找手机式“无线调试”页面。

可以构建一个体积小、可卸载的普通诊断 APK，展示实际 Android API、安装状态、可查询的 HOME 候选、设置入口及明确的查询失败原因。Android 包可见性和组件导出规则可能影响查询；“查不到”不能直接写成“系统没有”。只收集当前问题需要的内容。

优先沿用用户现有的手机传包方式。如果使用 SMB：

1. 确认哪台电脑真正运行共享服务及其实际地址。
2. 用户在系统连接窗口登录、选择共享文件夹，账号密码不需要发给 Codex。
3. 将明确版本的 APK 放入单独目录，复制后重新读取并校验 SHA-256。
4. 在电视验证共享入口能否显示和打开 APK；媒体浏览器可能只显示音视频。

给用户明确的本地 APK 文件路径和文件名。不要只提供临时下载网址，也不要不断追问已无必要的手机工具名称。

## 4. 分开验证安装和默认首页

### 4.1 APK 安装

先做最小可运行版本，确认 SDK/ABI、签名、包名和版本兼容。纯 Java/Kotlin 应用可减少不必要的原生 ABI 依赖；第三方库仍要检查实际兼容性。

如果只提示“安装失败”：

- 取得 ADB 安装原始错误、PackageInstaller 最终回调，或用户能提供的系统原文。
- 排查签名冲突、版本降级、损坏/不完整 APK、SDK/ABI、安装来源授权及厂商策略。
- 必要时用普通应用版和具备 HOME 声明的版本做受控对照，以判断是否和首页资格相关。
- `STATUS_PENDING_USER_ACTION` 仅表示等待用户确认，不能记录成安装成功；安装成功与否还应核对实际已安装版本。[PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller)

每次测试说明具体改变了哪个变量、要验证什么。不要用不断重命名 APK 或盲目降低 targetSdk 代替定位。

### 4.2 真正成为默认首页

独立 Launcher 应正确声明 `ACTION_MAIN`、`CATEGORY_HOME`、`CATEGORY_DEFAULT`，并提供适当的电视应用入口；对外组件按系统要求声明导出状态。

Android 10/API29 及以上，先检查 `ROLE_HOME` 是否可用，再通过系统流程请求用户选择；旧版本使用本机支持的 HOME 选择机制。角色可用性和厂商行为必须实测。[RoleManager](https://developer.android.com/reference/android/app/role/RoleManager)

必须分别确认：

1. 系统能够把新应用识别为 HOME 候选。
2. 默认 HOME/角色实际指向新应用。
3. 从另一个应用按遥控器物理 Home 键，真的回到新首页。
4. 用户方便时测试重启后是否保持；覆盖更新后再次检查。

“可以从应用列表打开”“能打开桌面选择设置”“有自动启动”都不能替代这些验证。ADB 模拟 Home 键的结果也不能代替物理遥控器测试。

原案例来自 TCL，其安装限制、白名单、设置组件和数据 provider 都属于特定系统。**不得把 TCL 包名、策略键、修改办法直接套到小米。** 如遇限制，先查实际组件、权限和有来源的证据，再评估可行路径。不要先卸载原桌面，也不要默认走 root、刷机或写系统分区来实现本任务。

## 5. UI 和遥控交互要求

先查看 Apple 官方 tvOS 主屏资料，明确参考版本，再编写简短设计说明。原生 Android 实现应完整服务于电视遥控场景。[Apple TV 主屏官方说明](https://support.apple.com/zh-cn/guide/tv/atvbad14dc6a/tvos)

- **构图**：全屏背景、合理安全边距、横向应用卡片、统一栅格和留白；首屏优先显示常用应用。
- **卡面**：优先使用真正的宽幅高清 banner。部分应用将正方形图标也声明为 banner，必须判断比例，不能直接裁切。自适应图标和普通透明图标按有效内容边界归一尺寸、光学居中，避免小图标套统一底板的廉价感。
- **焦点**：方向键移动清楚可见，选中项名称只有一个显示来源；初始进入就有有效焦点。放大、阴影、名称和滚动同步，焦点外扩不被父容器裁切。
- **动画和材质**：统一的玻璃层次、柔和高光和过渡；重计算、图片解码和模糊在后台完成，避免逐帧全屏模糊。系统关闭动画时能正确到达终态。
- **交互**：确认启动应用；长按或菜单整理、移动、隐藏；返回关闭当前面板并恢复焦点；控制中心提供电视设置、背景、应用管理和检查更新。
- **排序**：支持手动排序持久化；可以增加本桌面记录的启动次数排序，但不能将它描述成读取了所有应用的系统使用历史。
- **显示适配**：根据实际渲染分辨率、密度和字号适配；4K 面板不保证应用按 4K 渲染。检查长名称、大字号和空列表，不照搬手机控件尺寸。

## 6. 可更新背景和“最近在看”

按可用数据逐级实现：离线背景 → 可配置图片/JSON 源 → 经验证的本机观看数据。

- 自定义接口可以返回 `image_url`、`title`、`subtitle`；网络超时、响应大小、图片解码和缓存都应有界。失败时保留可用的离线背景。
- 小米的观看记录、推荐和播放协议需要单独验证。围绕实际原桌面/媒体应用的公开组件和用户授权提供的相关 APK 定点分析，不预设 provider URI、表字段或权限。
- 明确区分“打开视频应用”和“跳转到某部剧某一集继续播放”。没有确认深链、参数和权限时，只提供能验证的应用启动入口。
- 无权限或无记录时展示真实状态，不使用伪造观看记录，也不要求用户开放全部隐私数据。

## 7. 从一开始规划持续更新

首次安装后，减少反复手机传包：桌面提供“检查更新”，由用户自己的电脑提供版本清单和 APK。

建议契约：

```json
{
  "format_version": 1,
  "package": "你的实际应用包名",
  "version_code": 2,
  "version": "1.1",
  "bytes": 123456,
  "sha256": "这里应为实际APK的64位十六进制摘要",
  "notes": "本次更新说明"
}
```

上面的数值仅用于说明字段，不能直接发布。下载地址用实际摘要绑定不可变 APK，切换版本清单采用原子替换。

实现要求：

- 电脑端只提供明确发布的更新包，无目录列表；固定配置可重启复用，局域网访问使用独立授权。
- 电视核对实际下载大小、SHA-256、包名、较新版本号及与已安装应用一致的签名，再交给系统确认安装。摘要不是签名校验的替代。
- 清单/APK 设置合理大小上限、超时和取消行为；显示检查、下载、失败、无更新及安装结果。关闭或重建页面不应留下失控下载。
- 系统等待确认、用户取消、失败和成功分别保存；回调需关联实际会话，更新后查询真实安装版本。
- 每次提高 `versionCode`，长期保持包名、签名和 HOME 组件；用户排序与背景设置不能因普通升级丢失。
- 朋友自己的项目生成独立签名及更新授权。不要复用另一家庭的服务地址、访问令牌或签名文件。若导入已有 APK/源码，先确认是否具备原签名；不能承诺用新签名直接覆盖旧包。

## 8. 验证顺序与完成标准

先跑直接覆盖改动的快速检查，再扩到受影响部分；运行构建/测试脚本前先看内容，复用有效结果。使用模拟器时只管理本任务创建的实例，不停止其他项目的任务。

| 范围 | 必须留下的结果 |
| --- | --- |
| 构建与安装包 | APK 路径、包名、版本、SHA-256、签名、Manifest 与实际 SDK/ABI 兼容范围 |
| 真机安装 | 安装来源、原始结果、实际安装版本，不能只凭文件发送成功 |
| 默认首页 | HOME 解析/角色、物理 Home 键；重启未测则明确标记 |
| 遥控与显示 | 初始焦点、移动、确认启动、菜单/返回、长名称、大字号、空列表与隐藏后状态 |
| 背景 | 离线、正常更新、超时/坏响应；观看记录的无权限/无数据状态 |
| 更新 | 较新包成功、同版本拒绝、损坏/错误签名拒绝、取消与失败、更新后 HOME 和偏好保持 |
| 恢复 | 能进入电视设置、原桌面以及系统默认首页选择 |

截图和模拟器只能证明对应环境下的表现。每项结果注明是真机、模拟器、静态分析还是用户反馈，不要将它们混写为“小米电视全部通过”。

## 10. 本次经验中最重要的区别

- ADB 已打开 ≠ 已建立授权连接。
- APK 已发送 ≠ 安装成功。
- 普通应用能启动 ≠ 具有 HOME 资格。
- 打开桌面切换入口 ≠ 已设置默认桌面。
- 系统角色已选中 ≠ 已验证物理 Home 键和重启行为。
- 官方推荐图/测试图 ≠ 用户最近观看内容。
- 普通应用 ≠ 能直接使用所有系统私有接口。
- TCL 上可行 ≠ 小米上已验证。
- 改图标大小/背景颜色 ≠ 已实现完整 tvOS 质感。
